# Quant Fun — build plan (handoff)

Build a playable single-screen browser game, "Quant Fun": a fixed-camera isometric 2.5D pixel-art
trading office where the player is the Boss and runs one BTC 5m replay session with a four-person desk.
All UI copy is Vietnamese. Work only inside `B` = this folder (`.../scratchpad/build`). Do not publish
anything, do not touch git, do not fetch from the network (no CDN, no fonts, no APIs).

**Verified sprite facing (checked visually on all 21 legends; also stored in
`assets.json.spriteFacing`). Note: this is the opposite of the Pixel Agents convention, so do not
copy facing logic from the Pixel Agents source.**

| sprite key    | what it shows                         | use when moving on screen |
|---------------|----------------------------------------|---------------------------|
| `front-left`  | faces the viewer, looking screen-left  | down-left                 |
| `front-right` | faces the viewer, looking screen-right | down-right                |
| `rear-left`   | back to viewer, looking screen-left    | up-left                   |
| `rear-right`  | back to viewer, looking screen-right   | up-right                  |

Compute direction from the movement delta in real pixels (x% × room width, y% × room height):
`dy>0 ? (dx<0 ? 'front-left' : 'front-right') : (dx<0 ? 'rear-left' : 'rear-right')`.

## 1. Deliverables

`B/build.py` assembles from `B/src/{game.css, body.html, logic.js, ui.js}` + `assets.json` + `bars.json`:

1. `B/out/artifact/quant-fun.html` — page **fragment** for publishing: starts with
   `<title>Quant Fun</title>` and `<meta name="claude:viewport-fit-sides" content="cover">`, then
   `<style>`, markup, `<script>`. No `<!doctype>`, `<html>`, `<head>`, `<body>` tags.
2. `B/out/download/quant-fun.html` — the same content wrapped in a complete document
   (`<!doctype html><html lang="vi"><head><meta charset="utf-8"><meta name="viewport"
   content="width=device-width, initial-scale=1, viewport-fit=cover">…`). Must run from `file://`
   with zero network requests.

Both: all CSS, JS, images, font and data inline. No external URL anywhere except plain `<a href>`
credit links. Own CSS must include what the publish skeleton would add (`body{margin:0}`,
`[hidden]{display:none!important}`, `*{box-sizing:border-box}`), so both files look identical.
Target total size under ~2.2 MB (the 84 sprites are ~1 MB). Put each data URI in the HTML once:
build one JS object of URIs and set `img.src` from it; never repeat a URI in markup or CSS.

## 2. Hard requirements from the user (all must hold)

- Player is the Boss on load. Default team is ready; the game is playable with zero setup.
- Layout on desktop prioritises the room; BTC chart and decision panel sit beside it.
- Room: Pixel Agents room + desks, fixed isometric camera. Sprites switch by walking direction.
  A light step rhythm made from the existing standing poses (bob), no new art.
- Name **and current status** above every character's head.
- Loop: **Giao việc cho Quant** → **Next Candle** advances BTC 5m → Quant reports the SMA 10/30
  cross → Trader walks to the Boss's desk, **then** pops a speech bubble with the proposal →
  Risk Manager answers **Pass** or **Block with the reason** → Boss clicks **Approve** or **Skip**.
  An approved order fills (simulated) when the player advances to the next candle, at that
  candle's open. Portfolio Manager updates NAV, PnL, Cash, Exposure and the fill history.
  **Reset** restarts.
- Rules exactly as `logic.js`: long-only, capital 100,000 USD, default allocation 20%, position cap
  25% NAV, unit 0.001 BTC, half-spread 5 bps, fill at next bar's open. Show only candles already
  run (the snapshot's 48-bar window). A blocked proposal has **no Approve button**.
- Label **“Dữ liệu mô phỏng”** visible in the game.
- **Settings** (requested mid-task): a Settings panel where the player sets names and picks a
  “legend” (persona) for each role. Persona changes name + look in the room; business logic stays
  with the role.
- Asset credits kept in the game.
- No dependency on the private repo, Python, Node, CDN, API keys, MCP, Claude hooks or an exchange.

## 6. Flow, mission bar, controls

`const desk = new QuantLogic.Desk(BARS)`. Every user action calls `desk.action(name, data)` inside
try/catch (errors → inline `role="alert"` line in the decision card, never `alert()`), then
`render(desk.snapshot())`. The **new log entries** since the previous snapshot drive the room: each
entry has `role`, `text`, `kind` (`brief, assign, ack, cross, propose, pass, block, approve, skip,
fill, nofill, book`) and plays as a bubble on that role's actor, in order, ~650ms apart.

Proposal sequence (kinds `cross` → `propose` → `pass|block`):
1. Quant bubble “SMA 10 cắt lên/xuống SMA 30.”
2. Trader walks to the Boss (no bubble yet). Decision card shows “Trader đang mang đề xuất tới…”.
3. On arrival the Trader bubble pops: repo line + detail, e.g.
   “Đề xuất mở vị thế BTC. 20% NAV, giá tham chiếu $66,869.23.” (sell: “Đề xuất đóng vị thế BTC.
   Bán hết 0.298 BTC, giá tham chiếu $…”).
4. Risk bubble: “Pass. Đề xuất nằm trong giới hạn rủi ro.” or “Block. Tỷ trọng vượt giới hạn 25% NAV.”
5. Decision card becomes active: verdict badge + reason line
   (Pass buy: “Tỷ trọng 20% ≤ hạn mức 25% NAV.” · Pass sell: “Đóng vị thế không làm tăng rủi ro.” ·
   Block: “Tỷ trọng 50% > hạn mức 25% NAV. Giảm phân bổ rồi chờ tín hiệu kế.”).
   Pass → `#approve` and `#skip` visible. Block → **neither button exists in the visible UI**
   (`hidden`), Next Candle stays enabled (repo behaviour), Trader walks home after ~2.5s.
Logic state changes immediately; only the visuals are sequenced. While steps 1–4 play, Approve/Skip
are hidden; under reduced motion or when `window.QF_FAST === true` (test hook) all delays are 0
and walking teleports. Reset cancels every timer/animation and restores all actors (use a
sequence token).

Button enablement = repo `controls()`: `#assign` disabled when armed (label becomes “Quant đang
theo dõi”); `#next` disabled while a proposal is waiting or at the last bar; Approve/Skip only with
a proposal. Extra helper `#run` “Tua tới tín hiệu”: repeats Next Candle every ~110ms until a
proposal, a block or the end; toggles to “Dừng”; disabled when `#next` is; if not armed it does
nothing but point at step 1. Keyboard (ignored while typing in an input or when Settings is open):
`N` or Space = Next Candle, `A` = Approve, `S` = Skip. Show the keys as small hints on the buttons.

**Mission bar** (under the room) = the player's goal and next move, always visible:
- Goal line: “Mục tiêu: chạy hết 160 nến và kết phiên với NAV trên $100,000.” + session progress
  “Nến 30/160” with a thin progress bar.
- Six step chips, current one highlighted, done ones ticked:
  1 Giao việc · 2 Chạy nến · 3 Quant báo giao cắt · 4 Risk Pass/Block · 5 Boss quyết · 6 Khớp nến sau.
  Numbering is real order. State → step: not armed → 1; armed, nothing pending → 2; sequence
  playing → 3 then 4; proposal waiting → 5; pending order → 6 (after the fill → 2).
- Coach line (one sentence, the exact next action), e.g. “Bấm Giao việc cho Quant để bắt đầu.” /
  “Bấm Next Candle (N) cho tới khi SMA 10 cắt SMA 30.” / “Trader đang ở bàn bạn. Approve hoặc Skip.” /
  “Đã duyệt. Bấm Next Candle để khớp ở giá mở nến kế.” / “Risk đã Block. Giảm phân bổ xuống 25%
  trở xuống, rồi Next Candle chờ tín hiệu kế.” / end: “Hết phiên replay. NAV phản ánh vị thế còn
  mở nếu có.”
- The primary button for the current step gets the accent fill; others are quiet.
- On load the Boss already shows the opening bubble (repo's first log line) and step 1 is lit.
  No blocking intro overlay.
- End of session (index 159): a result strip in the mission bar — final NAV, PnL, number of fills,
  “đạt / chưa đạt mục tiêu” — and Reset becomes the accent button (“Chơi lại”).

## 8. Settings (naming + legends)

`#settings-open` opens an in-page dialog (`<dialog>` with `showModal()` and a fallback to a
fixed panel; closes with the button, Esc and backdrop click; focus returns to the opener).
Title “Cài đặt”. Three parts:

1. **Đặt tên** — text inputs (maxlength 18): “Tên bàn giao dịch” (default “Quant Fun Desk”, shown
   next to the title in the top bar) and one name per seat: Boss, Quant Analyst, Trader,
   Risk Manager, Portfolio Manager. Empty input falls back to the legend's name.
2. **Chọn legend** — five seat rows (Boss + the four roles; the role label never changes). Each
   row: current portrait + name, and the roster of all 21 legends as portrait buttons (crop the
   `front-right` sprite to head and shoulders with `object-fit/object-position`; `aria-pressed`;
   the roster grid wraps and may scroll inside the dialog).
   Picking a legend for a seat changes that seat's look and resets its name to the legend's name.
   A legend already used by another seat **swaps** with it. Each legend tile can preview its four
   angles (small row labelled front-left / front-right / rear-left / rear-right) on hover/focus or
   in a strip under the roster for the selected one.
3. **Chuyển động** — checkbox “Nhịp bước và hoạt cảnh” (on by default; off = no bob, instant moves).
   Button “Về đội mặc định”.

Roster display names come from `assets.json.legends` (the player can rename any seat). Default
Boss seat name is “Boss”; the other seats default to their legend's name.
The roster is the plain `legends` array (id, name) so more legends can be dropped in later.
Room dialogue stays the repo's generic desk lines for each role: never write lines that sound like
a legend's real views, catchphrases or opinions.

Persist team, names and the motion toggle in `localStorage` key `quantfun.settings.v1`, every
read/write in try/catch; the game must work when storage throws. **Reset does not wipe settings**
(it resets the session only). Settings changes never touch `desk`.
